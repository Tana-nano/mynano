# アップロードドクター 0.1.2 仕上げ試験と商品画像の撮影

出品前の最後の実機作業。0.1.1 の再試験で確かめきれなかった 3 点を確かめ、Booth の商品画像に使うスクリーンショットを撮る。
「守ること」は `docs/cowork-test.md` と同じ。特に次の 4 つを守る。

- 変更するのは、試験用プロジェクト `C:\UDTest\日本語フォルダ\UDテスト` だけにする。kip_ookami は開かない・変えない。
- VRChat にログインしない、アップロードしない。
- スクリーンショットには、他人の表示名・ID・メールアドレス・Windows のユーザー名を写さない。
  - 撮るのはウィンドウだけにする。画面全体やタスクバーは写さない。
  - 写り込んだら撮り直す。
- 操作できない作業（ダウンロードしたファイルの展開、ダブルクリック、ドラッグ＆ドロップ）はオーナーに頼み、その旨を記録する。

## F1 購入者と同じ手順での起動と警告（SmartScreen）

1. オーナーがブラウザで 0.1.2 の成果物をダウンロードする（購入者と同じく、Windows の中で操作する）。
   https://github.com/Tana-nano/mynano/actions/runs/36866245874/artifacts/11164446820
2. エクスプローラーの「すべて展開」で 2 回展開し、`C:\UDTest\0.1.2-browser\` の下に置く。
3. `upload-doctor.exe` をダブルクリックする。
4. 警告が出たら、**ボタンを押す前に**ウィンドウのスクリーンショットを撮る（`smartscreen-1.png`）。
5. 文面のとおりに進める（例:「詳細情報」を押す）。次の画面も、ボタンを押す前に撮る（`smartscreen-2.png`）。
6. 押したボタンの名前と、表示された文面をそのまま記録する。警告が出なかった場合は、そのことを記録する。
7. 起動したら、Enter を押さずにそのまま F2 へ進む。

## F2 実行日時（起動してから時間をおいた診断）

1. F1 で起動した画面を、そのまま **2 分以上** 置く。起動した時刻を記録する。
2. エクスプローラーから `C:\UDTest\日本語フォルダ\UDテスト` を画面にドラッグし、Enter を押す。ドラッグした時刻を記録する。
3. できたレポートの名前と「実行日時」を記録する。

期待: レポートの名前と実行日時が、起動した時刻ではなく、ドラッグした時刻（数十秒以内のずれ）になる。

## F3 読み込み記録の誤検出（Library を消して読み込み直す）

1. Unity がすべて閉じていることを確かめる。
2. `C:\UDTest\日本語フォルダ\UDテスト\Library` フォルダを削除する（試験用プロジェクトだけ）。
3. VCC の「Open Project」で UDテスト を開く。読み込み直しに時間がかかるので、終わるまで待つ。
4. Console のエラー件数を記録して、File > Exit で終了する。
5. UDテスト を exe にドロップし、結果を記録する。
6. `%LOCALAPPDATA%\Unity\Editor\Editor.log` に `Start importing` で始まる行が何行あるかを数えて、記録する。

期待:

- `Start importing` の行は数百行以上ある。
- それでも「分類できないエラー」は出ない（0.1.0 では 13 種類出ていた）。
- 出た場合は、根拠の行をそのまま記録する。

## F4 商品画像のスクリーンショット

コンソールは Windows ターミナルのまま、文字の大きさを少し大きくする（目安: 14〜16）。
ウィンドウの大きさは、横 1100〜1300 px・縦 700〜900 px ほどにする。結果の候補が全部収まるようにする。

### ng.png（原因が見つかったときの画面）

1. Unity で UDテスト を開き、`Assets\UDDemo\Demo.cs` を次の内容で作る。
   ```csharp
   using UnityEngine;
   public class UDDemo : MonoBehaviour
   {
       DynamicBone bone;
   }
   ```
2. コンパイルが終わり、Console に `DynamicBone` が見つからないというエラーが出たら、Unity を File > Exit で終了する。
3. UDテスト を exe にドロップする。
4. 結果が出たコンソールのウィンドウを撮る（`ng.png`）。
   - 「[NG] Assets 内のスクリプトがコンパイルエラーです」と、「足りない型」の Dynamic Bone の案内が写っていること。

### report.png（相談用レポート）

1. 今の診断でできたレポート（`ドキュメント\UploadDoctor\report-….txt` の最新のもの）を、メモ帳で開く。
2. 先頭から「原因の候補」の 1 件目と 2 件目までが入るように、ウィンドウの大きさを合わせて撮る（`report.png`）。
   - `<PROJECT>` などの伏せ字が写っていること。

### clean.png（問題が無いときの画面）

1. `Assets\UDDemo` フォルダと `UDDemo.meta` を削除する。
2. VCC から UDテスト を開き、Console のエラーが 0 件になったのを確かめて、終了する。
3. UDテスト を exe にドロップし、「結果: 問題は見つかりませんでした」が出たウィンドウを撮る（`clean.png`）。

### スクリーンショットの渡し方

`ng.png`・`report.png`・`clean.png`（F1 で撮れていれば `smartscreen-1.png`・`smartscreen-2.png` も）を、次の場所にアップロードする。

https://github.com/Tana-nano/mynano/upload/ccr-a0434aa8-q25t65/products/upload-doctor/images/screens

- ブラウザで GitHub にログインした状態で開き、ファイルをドラッグして「Commit changes」を押す。
- ドラッグできない場合は、オーナーに頼む。
- 個人情報が写っていないことを、アップロード前にもう一度確かめる。
