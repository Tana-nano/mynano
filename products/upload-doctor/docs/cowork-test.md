# アップロードドクター 実機試験手順（PC を操作できるエージェント向け）

オーナーの Windows PC で、画面とファイルを操作できるエージェントに渡す手順書。
CI（Linux・ライセンスなし）では確認できなかった項目を確かめる。結果は最後の「結果の書式」でまとめる。

## 守ること

- **オーナーの既存の Unity プロジェクトは変更しない。** 読み取り（診断にかけるだけ）は可。
  変更を伴う試験は、この手順で新しく作る試験用プロジェクトだけで行う。
- **VRChat へのアップロードはしない。** SDK の Build & Publish / Upload ボタンは押さない。VRChat にログインしない。
- **ログの取り扱い:** 結果に貼る Editor.log の行は、この手順で指定した行だけにする。
  Windows のユーザー名は `<USER>`、`usr_` / `avtr_` / `wrld_` で始まる ID は `<ID>` に置き換える。
  スクリーンショットには、他人の表示名・ID・メールアドレスが写らないようにする。
- 手順どおりに進まないとき（ボタンが見つからない、想定と違う画面が出る）は、無理に進めず、その時点の状況を結果に書いて止める。
- 試験後、試験用プロジェクトと展開したフォルダはそのまま残してよい（削除はオーナーが判断する）。
- VCC の「Pick New Folder」は、新規プロジェクトの既定の保存先も変えてしまう。使った場合は元の保存先を記録し、試験の最後にオーナーへ戻し方を伝える。

## 準備

1. ブラウザで GitHub にログインした状態で、オーナーから指定された成果物（`upload-doctor-<版>-win64`）をダウンロードする。
   Actions の成果物は zip の中に配布用の zip が入っているので、2 回展開する。
   エクスプローラーの「すべて展開」は zip と同じ名前のフォルダを作るため、同じ名前のフォルダが重なることがある。
2. `C:\UDTest\` を作り、その中に展開する。`upload-doctor.exe` の場所を記録する。
   ダウンロード・展開・ダブルクリック・ドラッグ＆ドロップができない場合は、オーナーに操作を頼み、その旨を記録する。
3. Unity Hub・VCC（VRChat Creator Companion）が入っていること、Unity のバージョンを確認して記録する。

## 試験項目

各項目について「結果の書式」の欄を埋める。期待どおりでなくても次の項目へ進んでよい。

### T1 起動とセキュリティ警告

1. `upload-doctor.exe` をダブルクリックする。
2. Defender / SmartScreen の警告が出たら、閉じる前に必ずスクリーンショットを撮り、その文面と、README の「導入手順」に書かれた操作で進めたかを記録する。
3. 黒い画面（コンソール）が開き、「Unity プロジェクトのフォルダをここにドラッグして Enter」と出ることを確認し、スクリーンショットを撮る。
4. T2 で使うのと同じプロジェクトフォルダをエクスプローラーからこの画面にドラッグし、Enter を押す。診断が始まり、結果が出ることを確認する（結果の記録は T2 で行うので、ここでは「出たかどうか」だけ）。
5. Enter で閉じる。

期待: 起動する。日本語が文字化けしない。画面へのドラッグでもパスが受け付けられる。

### T2 既存プロジェクトのドラッグ＆ドロップ（読み取りのみ）

1. Unity を終了した状態にする。
2. オーナーが普段使っているアバターのプロジェクトフォルダ（VCC の一覧にあるもの）を 1 つ選び、エクスプローラーで `upload-doctor.exe` の上にドロップする。
3. 表示された結果の画面全体をテキストでコピーする（コンソールのウィンドウで範囲選択 → Enter、またはスクリーンショット）。
4. `ドキュメント\UploadDoctor\` に `report-*.txt` ができたことを確認し、その中身を結果に貼る。
   （レポートはユーザー名・ID を伏せ字にしてある。伏せ字になっていない個人情報が見えたら、その事実を書き、該当部分は `<USER>` に置き換える）
5. Enter で閉じる。

期待: 「対象プロジェクト」の判定、Unity のバージョン、SDK の検出、パッケージの一覧に、実際の状態と違う点がない。
違う点があれば、実際の状態（VCC の画面に出ているバージョンなど）と並べて書く。

### T3 試験用プロジェクトを日本語を含むフォルダに作る

1. VCC で新しいアバタープロジェクトを作る。
   名前は `UDテスト`、場所は `C:\UDTest\日本語フォルダ\` とする（フォルダがなければ作る）。
2. VCC で Modular Avatar を追加できる場合は追加する（「Manage Project」→ パッケージ一覧）。できなければその旨を記録する。
3. 一度 Unity でプロジェクトを開き、読み込みが終わってエラーが無いことを確認したら、Unity を終了する。
4. `C:\UDTest\日本語フォルダ\UDテスト` を `upload-doctor.exe` にドロップし、T2 の 3〜5 と同じく記録する。
5. `C:\UDTest\日本語フォルダ\UDテスト\Packages\vpm-manifest.json` の中身をそのまま結果に貼る（個人情報は含まれない想定。含まれていれば伏せる）。

期待: 日本語のパスで落ちない。致命的（NG）な候補が出ない。「対象プロジェクト: 一致」になる。

### T4 Unity を開いたままの診断

1. 試験用プロジェクト `UDテスト` を Unity で開いたままにする。
2. その状態で `UDテスト` のフォルダを `upload-doctor.exe` にドロップし、結果を記録する。

期待: ログを読める、または「Unity を終了してから再実行」の案内が出る（どちらになったかを記録）。

### T5 コンパイルエラーを起こす（試験用プロジェクトのみ）

1. Unity で `UDテスト` を開いたまま、`Assets` に `UDTestBroken` フォルダを作り、`Broken.cs` というファイルを次の内容で作る。
   ```csharp
   using nadena.dev.modular_avatar.core;
   using UnityEngine;
   public class UDTestBroken : MonoBehaviour
   {
       void Start() { int x = "text"; }
   }
   ```
   （Modular Avatar を入れた場合も入れなかった場合も、この内容で行う）
2. Unity に戻ってコンパイルが終わるまで待つ。Console に赤いエラーが出ることを確認し、エラー行を結果に貼る。
3. Unity を終了する。
4. `UDテスト` を `upload-doctor.exe` にドロップし、結果を記録する。
5. `%LOCALAPPDATA%\Unity\Editor\Editor.log` から、次の行だけを結果に貼る（ユーザー名は `<USER>` に置き換える）。
   - 先頭 40 行
   - `-projectPath` または `-projectpath` を含む行とその次の 2 行
   - `error CS` を含む行すべて（最大 20 行）
6. `Assets\UDTestBroken` フォルダを削除し、Unity で開いてエラーが消えることを確認して終了する。

期待: 「[NG] Assets 内のスクリプトがコンパイルエラーです」の根拠に `Assets\UDTestBroken\Broken.cs`（区切りは `\` または `/`）が出る。
Modular Avatar を入れていない場合は、足りない型として Modular Avatar の案内が出る。

### T6 Unity Hub 以外からの起動のログ（任意）

T5 の 5 で `-projectPath` を含む行が見つからなかった場合だけ行う。
VCC の「Open Project」から Unity を起動し、読み込み後に終了して、同じく先頭 40 行と `-projectPath` の行を記録する。
