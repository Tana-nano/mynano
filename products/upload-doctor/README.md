# アップロードドクター for VRChat

VRChat のアバターが Unity からアップロードできないときに、**Unity を開かずに**プロジェクトのフォルダと Unity のログを調べて、原因の候補と「次にすること」を日本語で教えてくれる無料ツールです。

## できること

- **Unity が赤いエラーで開けない・VRChat SDK のメニューが出ないときでも使えます**（Unity の外から、ファイルを読むだけで調べます）
- **Unity のバージョン**が VRChat の推奨版と合っているかを確認します
- **VCC（VRChat Creator Companion）のパッケージ**が一覧どおりに入っているか、パッケージ同士の必要なバージョンが合っているかを確認します（例：「Avatar Optimizer は VRChat SDK 3.11.0 未満が必要ですが、3.11.0 です」）
- 旧方式の SDK との**二重導入**、SDK2 の設定の残り、日本語や長すぎるフォルダ名なども確認します
- Unity のログ（Editor.log）から**コンパイルエラー**（スクリプトの読み込みエラー）を、「アセットのもの」「VRChat SDK のもの」「その他」に分けて数えます
- **足りないもの**（例：Modular Avatar、Dynamic Bone、lilToon）を、エラーの文から推測して表示します
- 見つかった候補を「**確からしさ**（高・中・低）」付きで、可能性が高い順に並べます。根拠（どのファイルのどの行か）も表示します
- 困ったときに貼れる**診断レポート**（txt）を保存します。ユーザー名・プロジェクト名・ID は伏せ字になります

**プロジェクトのファイルは 1 つも書き換えません。** インターネットへの送信もしません。

## 対応環境

| 環境 | 対応 |
|---|---|
| Unity を使う Windows PC（アバターを作る・アップロードする PC） | ○ |
| PC VR / デスクトップ | VRChat を起動する必要はありません（どちらで遊んでいる方でも使えます） |
| Meta Quest 単機（PC なし） | × 非対応（Unity は PC で使うため） |

- Windows 10 / 11（64bit）。管理者権限は不要です。
- 対象は VRChat SDK3（Avatars）の Unity プロジェクトです。Unity・VRChat SDK は含まれていません。
- **確認の対象外**: シーンの中身（Avatar Descriptor、ボーン、ポリゴン数、パラメータ容量など）。これは Unity 内の VRChat SDK パネルが確認します。

## 導入手順

1. zip を展開し、中のフォルダ（`upload-doctor-0.1.0-win64`）を好きな場所に置きます。
2. **Unity を一度閉じます**（ログを読み取れるようにするためです）。
3. アバターの **Unity プロジェクトのフォルダ**（`Assets` と `ProjectSettings` が入っているフォルダ）を、`upload-doctor.exe` の上に**ドラッグ＆ドロップ**します。
   - `upload-doctor.exe` をダブルクリックした場合は、表示された画面にフォルダをドラッグして Enter キーを押します。
4. 結果が表示されます。上にあるものほど可能性の高い原因です。`→` の行が「次にすること」です。

初回起動時に Windows から「WindowsによってPCが保護されました」と表示される場合があります。
「詳細情報」→「実行」で起動できます（個人が配布するソフトでよく出る表示です）。

## 結果の見かた

```
原因の候補（上ほど可能性が高い順）
 1. [NG]   確からしさ:高  Assets 内のスクリプトがコンパイルエラーです（3 件、延べ 3 回。SDK パネルが出ない原因になります）
             根拠: Assets/FixtureShop/Scripts/FixtureBone.cs(4,12) error CS0246: The type or namespace name 'DynamicBone' could not be found …
             → エラーの出ているファイルがどのアセット（商品）のものか確かめ、導入手順の抜け（必要なパッケージ）を確認してください
             ※ ログにある＝今も出ているとは限りません。Unity を開いてコンソールで再確認してください
 2. [注意] 確からしさ:中  足りない型・名前空間があります（2 個）
             根拠: 'nadena' → Modular Avatar（または NDMF）が入っていません。商品の導入手順に従って VCC で追加（確からしさ:低）
 3. [注意] 確からしさ:中  Unity のバージョンが推奨と少し違います（2022.3.6f1 / 推奨 2022.3.22f1）
             → 推奨版（2022.3.22f1）の Unity で開き直してください（VCC からインストールできます）
問題なしの項目: VRChat SDK が入っています（com.vrchat.avatars 3.10.1, com.vrchat.base 3.10.1）

結果: NG 1 件、注意 2 件
```

| 表示 | 意味 |
|---|---|
| `NG` | アップロードや SDK パネルを妨げる原因です |
| `注意` | 原因になりうるものです |
| `情報` | 問題とは限りませんが、知っておくとよいことです |
| 確からしさ `高` | VRChat の公式ドキュメントに、その原因がはっきり書かれています |
| 確からしさ `中` | 公式に近い情報はありますが、条件や実物での現れ方がまだ確かめられていません |
| 確からしさ `低` | 解説記事などの情報にもとづく推測です。外れることがあります |

- **表示された対処を行う前に、必ずプロジェクトのバックアップを取ってください。**
- 「Unity のログ（Editor.log）」は、**最後に開いた Unity のプロジェクト**のものです。別のプロジェクトのログだと分かったときは、そう表示して確からしさを「低」に下げます。調べたいプロジェクトを Unity で一度開いてから閉じ、もう一度実行すると確実です。

## 使い方（細かい指定）

コマンドプロンプトから次のように指定することもできます。

| 指定 | 動作 |
|---|---|
| `upload-doctor.exe <フォルダ>` | そのプロジェクトを調べます |
| `--editor-log <ファイル>` | Unity のログの場所を指定します（既定は `%LOCALAPPDATA%\Unity\Editor\Editor.log`。1 つ前の起動のログ `Editor-prev.log` を調べたいときなど） |
| `--verbose` | 根拠をすべて表示し、読んだファイルの一覧も表示します |
| `--out <フォルダ>` / `--no-report` | レポートの保存先を変えます / 保存しません |
| `--rules <ファイル>` | 判定の規則表を差し替えます（下記） |
| `--no-pause` | 終了時に Enter キーを待ちません |
| `--version` | バージョンを表示します |

### 診断レポート

`ドキュメント\UploadDoctor\report-日付-時刻.txt` に保存されます。
アバターや衣装の作者さま、詳しい友人に相談するときは、このファイルの中身を貼ると話が早く進みます
（Unity のバージョン、入っているパッケージ、エラーの内容がまとめて伝わります）。

## 設定（規則表）

判定の基準（推奨の Unity バージョン、ログの読み方、足りないもののヒント）は `rules.json` という規則表にまとまっています。
VRChat の推奨が変わったときは、規則表を更新した版を配布します。規則表の日付から 90 日を過ぎると「古い可能性があります」と表示します。

## 出品者のみなさまへ

アバター・衣装・ギミックの商品ページや導入手順に「アップロードできないときはアップロードドクターを実行して、結果（レポート）を送ってください」と書いていただいて大丈夫です。
Unity のバージョンや入っているパッケージを聞き返す手間が減ります。Booth の商品ページへのリンクでご紹介ください。

## 既知の制限

- **Windows で普段どおりに使っている Unity のログ（Editor.log）全体では、まだ確認できていません**（未検証）。確認に使ったのは次のものです。
  - Unity 2022.3.22f1 の本体を起動して得たログの先頭部分。ライセンス認証の前で止まるため、プロジェクトの読み込みより前までです。
  - Unity に同梱されているコンパイラが出すエラーの文。
  - VRChat 公式のアバター用テンプレートと、公開されているパッケージのファイル。
  - 公開されている質問の文から作った、合成のログ。
  実際のログで一致しない行があるかもしれません。おかしな結果が出たら、レポートを添えてお知らせください。
- 別のプロジェクトのログかどうかの判定は、ログの先頭に Unity の起動時のフォルダが書かれている場合だけ行えます（未検証）。書かれていなければ「対象プロジェクト: 不明」と表示されます。
- アップロード失敗のメッセージ（「Failed to build avatar」など）は、公開されている質問の文から作った規則で探しています。網羅的ではありません。
- Unity を起動したままだとログを読めないことがあります（未検証）。読めなかったときは「Unity を終了してから再実行」と表示します。
- VCC の記録のうち「確定したバージョン」（`locked`）の形は、実物では確認できていません（未検証）。
- パッケージが必要とするバージョンは、`3.x.x` のような書き方と、`>=3.7.0 <3.11.0` のような比較だけを判定します。それ以外の書き方は判定しません。
- 確からしさ「低」の候補は推測で、外れることがあります。
- シーン・プレハブ・アニメーターの中身は見ません。VRChat アカウント側の問題（信頼ランク、ログインしているアカウントの種類）は診断できません。
- ドラッグ＆ドロップでの起動、日本語を含むフォルダ名での動作は、Windows 実機では未検証です（自動テストで Windows 上の起動と診断の流れまでは確認しています）。

## 取り扱うデータ

- 読むのは、指定したプロジェクトのフォルダにある設定ファイル（`ProjectSettings`、`Packages` の中）と、`Assets` の中のフォルダ名、Unity のログだけです。画像やモデルの中身は読みません。
- 保存するのは診断レポート（txt）だけです。レポートでは、ユーザー名・プロジェクトのフォルダ名・VRChat の ID・メールアドレスを伏せ字にします。パッケージの名前とバージョンは伏せ字にしません。
- インターネットへの送信は一切しません。
