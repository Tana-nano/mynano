# V睡ログ — 企画書 (concept)

## Step 1: コンセプト

| 項目 | 内容 |
|---|---|
| 商品種別 | PC アプリ（Windows、常駐型 CLI + ローカル HTML レポート。GUI は後回し） |
| 対象ユーザー | VR 睡眠（V睡）を習慣にしている PC VR ユーザー。OyasumiVR 利用者が中心 |
| 提供体験 | 寝る前に起動しておくだけで、翌朝「何時に寝落ちして何時に起きたか」「どのワールドで、誰と一緒だったか」「寝ている間に誰が来たか」が記録されている。週次で睡眠時間の推移と "一緒に寝た回数" が見える。Pokémon Sleep のように「起きるのが楽しみ」になる |
| 販売形態 | 通常版 **¥800** ／ 支援版 **¥1,500**（機能同一）。有料の別売り付属品は発売時なし |
| 参考作品 | OyasumiVR（無料）: 検知・ミュート・ポーズ。**記録・分析は無い**。おやすみレコーダー（有料）: 来客時だけ OBS 録画。**同じ隙間で成立している前例** |
| 差別化 | 「睡眠を記録して振り返る」専用品が無い。OyasumiVR を置き換えず、隣に置く |
| 対応環境 | PC VR ○ / デスクトップ △（ログ由来の記録のみ、動き検知不可） / **Quest 単機 ×** |
| AI 製リスク | 画像は生成しない。共有カードは文字＋数値のみを Pillow で描画。フォントは Windows 標準（Yu Gothic / Meiryo）を実行時に参照し同梱しない |

### ユーザーの一日での位置

1. 就寝前: VRChat と OyasumiVR を起動、本ツールも起動（自動起動設定可）
2. 就寝中: 何もしない。ツールが OSC とログを見て記録
3. 起床後: 「今夜のまとめ」がターミナル/HTML で見える。任意で X 用カード画像を出力
4. 週末: 週次レポート（合計睡眠、平均入眠時刻、よく一緒に寝た人）

## Step 2: 技術的実現可能性

### 必要な技術要素と一次情報

| 要素 | 内容 | 出典 | 状態 |
|---|---|---|---|
| VRChat OSC 出力 | 既定で 9001 へ送信。`/avatar/parameters/<Name>`（int/float/bool） | https://github.com/vrchat-community/osc/wiki | 確認済 |
| **頭の姿勢の出力** | `/tracking/vrsystem/head/pose`（6 floats、読み取り専用）を VRChat が送信。OSCQuery で `/tracking/vrsystem` を公開したアプリが受け取れる | https://github.com/vrchat-community/osc/wiki/OSCQuery（受信対象パスとして明記） / 検索要約 https://wiki.vrchat.com/wiki/OSC | **アドレスは確認済。6 floats の意味（位置 m / 回転 euler?）と送信レートは未確認** |
| OSCQuery | mDNS で VRChat が受信アプリを発見し、**複数アプリに同時送信**できる。OyasumiVR も OSCQuery 対応（v1.11.0）なので 9001 の取り合いにならない | https://github.com/vrchat-community/osc/wiki/OSCQuery / OyasumiVR CHANGELOG | 確認済（Python 実装ライブラリの選定は未） |
| VRChat ログ | `%LOCALAPPDATA%Low\VRChat\VRChat\output_log_*.txt`。`OnPlayerJoined / OnPlayerLeft / Joining wrld_… / Entering Room: / OnLeftRoom` | VRCX `Dotnet/LogWatcher.cs` | **実ログ未取得（形式差分は未検証）** |
| OyasumiVR 連携 | スリープモード切替時に任意 OSC を送る「OSC Automations」（v1.6.0〜）。送信先は現状 VRChat（OSCQuery）。**任意ホスト:ポートへ送る "Custom target" は CHANGELOG の [Unreleased]**（2026-09-07 マージ、未リリース） | https://github.com/Raphiiko/OyasumiVR/blob/develop/CHANGELOG.md / PR #299 | 確認済 |

### 睡眠検知の設計（論点 1 の背景）

OyasumiVR に「寝た」と教えてもらう経路は、今日時点では 2 つとも条件付き:

- (a) OyasumiVR → VRChat へアバターパラメータ送信 → VRChat が OSCQuery で本ツールにも配る。**ただし VRChat はアバターに存在するパラメータしか外に出さない**ので、購入者が Unity でパラメータを 1 個足す必要がある（導入障壁）
- (b) OyasumiVR の Custom OSC target で本ツールに直接送る。**未リリース機能に依存**

したがって **本ツール自身が `/tracking/vrsystem/head/pose` から動きを見て入眠/起床を判定する**のを主経路にし、(a)(b) は「あれば同期する」オプションにするのが堅い。
自前検知は VR のみ。デスクトップモードは「ログ由来（入室〜退室、同席者）」だけ記録する。

### この環境で検証できる範囲 / できない範囲

| 検証できる（模擬 VRChat・フィクスチャ） | できない（未検証として README に書く） |
|---|---|
| OSC 受信、head pose 列から入眠/起床を判定するロジック | 実機 VRChat の head pose の**単位・レート・座標系** |
| ログ追記→同席者・ワールドの抽出、日跨ぎ、複数ログファイル | 実ログの最新形式（`(usr_…)` の有無など） |
| セッション集計、週次レポート、カード画像の生成 | OSCQuery の mDNS が実 VRChat に発見されるか |
| 設定ファイル、ポート競合時のエラー表示 | OyasumiVR との同時起動での挙動 |

→ 判定ロジックは**閾値・レート・単位を全部設定可能**にし、初回は「感度」プリセットで吸収する。実機データが取れ次第 fixture に入れて閾値を確定する。

### 失敗しやすい点

- ログ形式変更で同席者検出が止まる → 正規表現を設定で差し替え可能に、検出ゼロが続いたら警告
- OSCQuery の mDNS が Windows Firewall で塞がれる → 従来の固定ポート受信（9001）にフォールバック、README に手順
- Defender SmartScreen 警告 → README に定型説明
- 他人の表示名を保存する（論点 3）

## Step 3: Go / No-Go

**Go（条件付き）**。差別化（記録・分析専用品が無い）、価格根拠（隣接商品帯）、検証可能な設計（自前検知＋模擬環境）が揃う。
条件: 論点 1 で「自前検知を主経路」に合意すること。OyasumiVR 必須設計にすると未リリース機能待ちになる。

## 本体機能と付属品（2026-09-29 決定）

### 本体（通常版・支援版共通）に入れるもの
| 機能 | 理由 |
|---|---|
| 今夜のまとめ（入眠・起床・ワールド・同席者・来客） | 核 |
| 週次レポート（合計睡眠、平均入眠時刻、連続日数） | 「起きるのが楽しみ」の源 |
| 共有カード（既定は人数のみ） | 拡散＝集客 |
| 来客リスト＋「お礼済み」チェック | 翌朝の行動につながる |
| CSV エクスポート | データは利用者のもの、という安心材料 |
| おやすみ／おはようのチャットボックス自動送信（任意 ON） | `/chatbox/input`。検知結果の可視化にもなる |
| 実績（文字バッジ：初 V睡、7 日連続、累計 100 時間 等） | 画像なしのゲーミフィケーション |

### 無料で配るもの
- **おやすみレコーダー連携**: 来客時刻をチャプター用テキストで出力（相互送客）
- **対応ギミック仕様の公開**: 本体が `/avatar/parameters/VsuiLog/*` を送る仕様を公開し、他の作者が「V睡ログ対応」ギミックを作れるようにする（モデルは他人、規格はこちら）

### 保留（発売 1 ヶ月の反応を見て判断）
- Discord 通知（Webhook）: 支援版で先行提供 → 本体に統合
- 起こし機能（時刻・来客トリガーで音＋パラメータ送信）: 実機未検証が多いため v1.1 以降
- 環境音: 音素材の AI 製リスクがあるため扱わない

## 論点の記録（決定前の提案）

### 論点 1: 睡眠検知の主経路
- **提案**: 自前検知（head pose）を主、OyasumiVR 同期を任意
- **理由**: 上記のとおり OyasumiVR 経由は Unity 作業か未リリース機能が要る
- **選択肢**: A) 提案どおり / B) OyasumiVR 必須（Custom target リリース待ち、導入は楽） / C) 両方なし＝ログのみ（入室〜退室を睡眠とみなす。精度は落ちるが最小）
- **確認**: どれにしますか？（推奨 A）

### 論点 2: 販売形態と価格
- **提案**: 有料 ¥1,000、単体
- **理由**: おやすみレコーダーと同帯。無料版を作ると "記録が見たい" という核が無料になり有料版の理由が薄い
- **選択肢**: A) ¥1,000 単体 / B) ¥800 本体＋週次レポート/カードを ¥500 拡張 / C) 無料＋支援版 ¥1,000（機能同一）
- **確認**: どれにしますか？（推奨 A）

### 論点 3: 同席者（他人）の記録
- **提案**: 表示名と `usr_` ID を**ローカルにだけ**保存。共有カードは既定で「人数」のみ、名前は本人がオンにした時だけ
- **理由**: 「誰と寝たか」は商品の核だが、他人の名前入り画像が拡散すると炎上リスク。VRChat 利用規約上も収集の扱いは慎重に
- **選択肢**: A) 提案どおり / B) 名前を一切保存しない（人数と時刻のみ） / C) 既定で名前入りカード
- **確認**: どれにしますか？（推奨 A）

論点が決まったら `/vrc-spec` へ。
