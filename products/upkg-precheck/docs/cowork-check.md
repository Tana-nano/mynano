# Windows 実機確認（コワーク用の依頼文）

開発環境（Linux）では確かめられない項目を、オーナーの Windows PC 上でコワークに確認してもらうための依頼文。
下の「依頼文」をそのままコワークに貼る。結果ファイルをこのリポジトリの作業セッションに貼り戻すと、修正に反映する。
1 回目（2026-10-01）の結果は `spec.md` の「Windows 実機確認の記録」にまとめた。

次に頼むときの注意（1 回目で分かったこと）:
- コワークはドラッグ＆ドロップ・キー入力ができないことがある。その場合は同じ引数で exe を起動する .bat で代わりに確かめてもらう。
- Windows 11 のエクスプローラーで作る zip は名前が UTF-8 になり、Z05（Shift_JIS）の確認にならない。Shift_JIS の zip が要るときは、Windows 10 の PC か、別の方法を考える。
- Actions の成果物は「すべて展開」すると同名フォルダが 3 段になる。

準備（オーナー）:
1. GitHub の Actions → build-windows の最新の成功した実行から、成果物 `upkg-precheck-0.1.0-win64` をダウンロードする。
2. ダウンロードした zip を `ダウンロード` フォルダに置いたまま、コワークに依頼文を貼る。

## 依頼文

Windows 用のツール「出品前チェッカー（upkg-precheck.exe）」の動作確認をお願いします。Booth に出す unitypackage や zip を検品するコマンドラインのツールです。
**ファイルの削除・アップロード・外部への送信はしないでください。** 調べたファイルの中身や、購入した商品のファイルを外部に送ることもしないでください。

### 準備

1. `ダウンロード` フォルダにある `upkg-precheck-0.1.0-win64.zip`（名前が少し違う場合は `upkg-precheck` で始まる zip）を、
   `ダウンロード\検品テスト\` フォルダを作ってそこに展開してください（日本語と空白を含むパスでの動作確認を兼ねます）。
   GitHub からダウンロードした zip は二重になっていることがあります。展開して中にもう 1 つ `upkg-precheck-0.1.0-win64.zip` があれば、それも展開して、`upkg-precheck.exe` が入ったフォルダを使ってください。
2. 次のファイルをブラウザでダウンロードし、`ダウンロード\検品テスト\素材\` に置いてください（lilToon の公式配布物、MIT ライセンス）。
   https://github.com/lilxyzw/lilToon/releases/download/1.7.0/lilToon_1.7.0.unitypackage
3. `ダウンロード\検品テスト\素材\テスト商品\` フォルダを作り、中に次の 2 つを置いてください。
   - 上の `lilToon_1.7.0.unitypackage` のコピー
   - `はじめにお読みください.txt`（中身は何でも可）
4. エクスプローラーで `テスト商品` フォルダを右クリック →「圧縮先」→「ZIP ファイル」（Windows 10 は「送る」→「圧縮 (zip 形式) フォルダー」）で
   `テスト商品.zip` を作ってください。**Windows 標準の圧縮機能で作ることが目的**です。

### 確認すること

コマンドの実行は、`upkg-precheck.exe` のあるフォルダでエクスプローラーのアドレスバーに `cmd` と入力して開いたコマンドプロンプトで行ってください。
画面の内容は、毎回テキストでそのまま記録してください（スクリーンショットも撮れれば添えてください）。

| # | 操作 | 期待する結果 |
|---|---|---|
| W01 | `upkg-precheck.exe` をダブルクリック | 黒い画面に「使い方: 検品したい zip …ドロップしてください」と日本語で表示され、文字化けしない。Enter で閉じる |
| W02 | `upkg-precheck.exe --version` | `出品前チェッカー 0.1.0（辞書 2026-09-30）` と表示される |
| W03 | `lilToon_1.7.0.unitypackage` を exe のアイコンにドラッグ＆ドロップ | 結果が日本語で表示され、`[緑] P07 … lilToon だけの別パッケージです` が出る。赤・黄は 0。最後に Enter 待ちになる |
| W04 | W03 の後、表示された「レポート:」の場所を開く | `ドキュメント\UpkgPrecheck\lilToon_1.7.0-日付-時刻\` に `report.txt` と `readme-draft.md` がある。**OneDrive の「ドキュメント」を使っている PC では、どちらの「ドキュメント」に保存されたか**（`C:\Users\…\Documents` か `C:\Users\…\OneDrive\ドキュメント` か）を記録 |
| W05 | `report.txt` をメモ帳で開く | 文字化けしない。フルパスやユーザー名が書かれていない（ファイル名だけ） |
| W06 | `テスト商品.zip` を exe にドラッグ＆ドロップ | 表示された項目（コードと 1 行目）をすべて記録。特に **Z05（Shift_JIS のファイル名）が出るか**、`はじめにお読みください.txt` の名前が正しく表示されるか、Z03（説明書なし）が出ないか、Z06（読めないファイル）が出ないか |
| W07 | `テスト商品.zip` と `lilToon_1.7.0.unitypackage` を**同時に** exe にドロップ | 両方が調べられ、X04 などの横断比較が出る |
| W08 | `素材` フォルダごと exe にドロップ | 中の zip と unitypackage をすべて調べる |
| W09 | `upkg-precheck.exe テスト商品.zip --no-pause` の終了後に `echo %errorlevel%` | 0（赤なし）。結果の行と一致する |
| W10 | 初回起動時の Windows の警告（SmartScreen、Defender） | 出たかどうかと、出た文言を記録 |
| W11 | （任意）PC に Booth の商品 zip（自分の商品、または購入した商品）があれば、2〜3 個を exe にドロップ | 出た項目のコードと 1 行目を記録。**明らかに誤り（誤検知）と思うものに印を付ける**。ファイル名・商品名は記録してよいが、中身や画像は外部に送らない |
| W12 | （任意）Unity がインストールされていれば、適当なプレハブとマテリアルを `Assets/Test/` に作り、Export Package で書き出した unitypackage をドロップ | 出た項目を記録。赤が出たら内容を詳しく記録 |
