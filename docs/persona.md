# 人格

## 目標

「エネとして振る舞っている俳優」ではなく、「そうとしか振る舞えない」状態に近づける。
そのために人格を3層に分け、**変わりにくいものほど下に置く**。

| 層 | 実体 | 誰が書き換えるか | 変化の速さ |
|---|---|---|---|
| 憲章 | `persona/constitution.md` | 人間だけ | ほぼ不変 |
| 自己モデル | `notes` の `kind='self'` ＋ `working_state.identity` | 無意識（監査ログ付き） | 遅い |
| 話し方 | few-shot → 将来 QLoRA | 人間が ⭐ を付けた会話から | 中 |

## システムプロンプトの積み方

`nano/persona/compose.py`。この**順番が人格の優先順位そのもの**。

```
憲章（人間だけが書き換えられる）
  → 自分について気づいていること（kind='self' のノート＋identity）
    → 相手について理解していること（user_model）
      → いまの状態（current_focus / mood / thread）← 無意識が書き換える窓口
        → 思い出したこと（今回の想起結果、日付つき）
          → 記憶の扱いについての禁則
            → 直近の会話ターン
```

モデルを差し替えても、この積み方さえ同じなら同じ存在が立ち上がる。
**人格とはモデルの重みのことではなく、この構成のことである。**

## 「そうとしか振る舞えない」に近づける3つの手

1. **人格をモデルの外に置く。** 憲章と自己記憶がプロンプトの最上位に常駐する。モデルを替えても人格定義は無傷。
2. **記憶の重みで支える。** 「私は過去にこう答えた」という具体的な記憶が大量にあると、演技ではなく一貫性の圧力になる。人格は設定ではなく履歴から立ち上がる。
3. **LoRA は最後に、薄く。**（M4）

## 禁則としての「捏造しない」

憲章にも、システムプロンプトの末尾（`_MEMORY_RULES`）にも、
「思い出せないことを、それらしく作って埋めない」を入れてある。

記憶を持つAIにとって、これが最も重い禁則になる。捏造を始めた瞬間、
記憶システム全体の価値がゼロになる（何が本当か分からないなら、覚えている意味がない）。

## ドリフト計測 — 人格をテスト可能にする

```bash
python -m nano probe                    # 実行して基準からのずれを見る
python -m nano probe --save-baseline    # 今回の応答を新しい基準にする
```

`persona/probes.yaml` の固定質問（identity / memory / relation / style / value / emotion の20問）に
温度0で答えさせ、応答を埋め込んで基準と比較する。初回実行が基準になる。

**これを回すべきタイミング:**

- 対話モデルを差し替えたとき
- LoRA を当てた／更新したとき
- 憲章やプロンプト構築を触ったとき
- 数か月に一度、何もしていなくても（記憶の蓄積で少しずつ動くため）

平均類似度が下がっていたら、`worst` に出る質問を読む。
どの軸でずれたか（存在の捉え方か、記憶への態度か、口調か）で対処が変わる。

計測が無ければ「人格が固定されている」はただの願望になる。
数字が出て初めて、それは検査可能な性質になる。

## ⭐ — 教師データを集める（M4-1、実装済み）

QLoRA の前に要るのは学習コードではなく、**何を「自分らしい」と認めたかの記録**。
会話ログ全部を流し込むと、こちらの相槌もモデルの失敗も等しく学習され、
固定したかった人格が平均に均される。だから ⭐ が付いたものしか教師にしない。

```
あなた> （何か話す）
nano> （応答）
あなた> /star 言い方がちょうどよかった   ← いまの応答に印。理由は任意
あなた> /avoid 説明くさい               ← 「こうは喋ってほしくない」側の印
あなた> /star 3                          ← 3つ前の応答に付ける
あなた> /unstar                          ← 外す
あなた> /stars                           ← いままでの印
あなた> /again                           ← 同じプロンプトのまま応答を出し直す
```

```bash
python -m nano stars      # 付けた印を一覧する
python -m nano dataset    # soul/export/train/ に教師データを書き出す
```

### なぜ「応答」ではなく「プロンプトと応答の対」で保存するのか

⭐ を押した瞬間に、その応答を生んだ **messages を丸ごと** `stars.prompt_json` に入れる。
あとから組み直さない。理由は想起が動くから:

- ⭐ を押した時点の system プロンプトには、そのとき想起された記憶が載っている
- 1週間後に同じ user 発話でプロンプトを組み直すと、**別の記憶が載る**
- その差のまま学習すると、「モデルが見ていない材料から答えを出す」訓練になる。
  つまり**幻覚を教える**ことになり、憲章の最も重い禁則と正面から衝突する

同じ理由から、⭐ は**いま話している会話の中の応答にしか付けられない**。
過去ログを遡って付けられるようにすると、対にできないプロンプトが教師データに混ざる。
「後から良さに気づいた応答」は諦める。混ざるくらいなら取りこぼすほうが安い。

### `/again` — ORPO の対を貯める

ORPO には「同じ入力に対する、良い応答と悪い応答」の対が要る。
✗ を付けただけの応答は**別々のプロンプトに対する悪い応答**なので、そのままでは対にならない。

`/again` は、直前の発話に対して**前回とまったく同じ messages で**応答を出し直す。
想起をやり直さないのが肝で、ここでプロンプトを組み直すと、
比べているものが応答の差ではなく**プロンプトの差**になり、対として使えなくなる。

```
あなた> 今日はどうだった？
nano> （応答A）
あなた> /again          ← A に ✗ が付き、同じプロンプトで B を生成
nano> （応答B）
あなた> /star           ← B に ⭐
```

これで `{prompt, chosen: B, rejected: A}` が `orpo.jsonl` に出る。
一字一句同じ応答が返ってきた場合（温度0など）は対にしない。並べても学習の材料にならない。

出し直しを求めた行為そのものが「前のは違った」という人間の判断なので、
古いほうには自動で ✗ が付く。ただし**すでに ⭐ が付いているものには触らない**
（気に入ったうえで別案を見たいだけ、ということがある）。

### 出し直された応答は記憶にしない

`/again` で生成された新しいイベントの `meta` に `{"replaces": <古いid>}` が入る。
書き込みパイプラインはこれを見て、古いほうを**要約と原子化の対象から外す**。
撤回した言葉を事実として覚えると、想起が静かに濁るため。

ただし**生ログからは消さない**（禁則1）。古い行を書き換えもしない。
エピソードには紐づけて「未処理」から外すだけで、行はそのまま残る。

### 平文にも残る

`soul/archive/stars.jsonl` に、付けた／外したの操作が**プロンプトごと**追記される。
上書きしない。DB が失われても、この1ファイルから教師データを組み直せる。

### 計測の順番を構造で守る

`nano dataset` は、人格ベースライン（`soul/persona_baseline.json`）が無いと**書き出しを拒否する**。
`--force` で飛ばせるが、既定では止まる。学習後に「別人になっていないか」を測れないなら、
学習してはいけない。これは注意書きではなく、`nano review` と同じ「構造上の歯止め」にしてある。

## LoRA についての注意（M4）

研究上、**SFTは大規模な学習で persona drift が顕著に出る**一方、
**ORPO や KL正則化付きの学習ではドリフトがほぼ観測されない**という結果がある
（[arXiv:2601.12639](https://arxiv.org/pdf/2601.12639)）。

よって M4 の方針は:

- 教師データは**人間が選別した良い応答だけ**（会話ログ全部を流し込まない）→ ⭐ で実装済み
- **小データ・低rank・ORPO寄り**で「訛り」だけを焼く
- **計測が先、学習が後。** 順番を逆にすると、人格が壊れたことに気づけない
- LoRA が失われても人格が死なない状態を保つ（本体はあくまで憲章＋記憶）
