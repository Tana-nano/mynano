# モデルを差し替える

このプロジェクトの第一原理は「モデルは交換可能な臓器で、記憶ストアが本体」。
それを実際に成立させているのが、ここに書く2つの仕組み。

- **同一性の記録** — どの埋め込み空間で作った記憶かを魂に刻み、食い違ったら起動を止める
- **キャリブレーション** — しきい値を絶対値ではなく、そのモデルの分布に対する相対位置で持つ

この2つが無いと、モデルの差し替えは交換ではなく**破壊**になる。

---

## 対話モデル（llama-server）を差し替える

こちらは気楽でよい。`config.toml` の `[llm]` を書き換えて再起動するだけ。
人格は憲章（`persona/constitution.md`）と記憶が担っているので、モデルが変わっても引き継がれる。

差し替えたら**必ず人格プローブを回すこと**。

```bash
python -m nano probe        # 基準からのずれを測る
```

平均類似度が大きく落ちていたら、`worst` に出る質問を読む。
どの軸でずれたか（存在の捉え方か、記憶への態度か、口調か）で対処が変わる。
詳しくは [persona.md](persona.md)。

---

## 埋め込みモデルを差し替える

こちらは慎重に。**記憶の座標系そのものが変わる。**

異なるモデルで作ったベクトルを同じ空間で比べても意味は無い。にもかかわらず、
次元数さえ合っていればコサイン類似度は「それらしい数字」を返してしまう。
黙って壊れるので、`soul.db` に埋め込み空間の名前（`multilingual-e5-large@1024` など）を
記録し、起動のたびに照合している。

食い違うと、こう出て起動が止まる:

```
埋め込みモデルが変わっています。
  魂に記録されている: multilingual-e5-large@1024
  いま使おうとしている: ruri-v3-310m@1024
既存の 4213 件のベクトルは前のモデルで作られたもので、別のモデルのベクトルと
比べても意味がありません（想起が静かに壊れます）。

どちらかを選んでください:
  1. 記憶を新しいモデルで埋め直す:  nano reembed
  2. 元のモデル（multilingual-e5-large@1024）に config.toml を戻す
```

### 手順

```bash
# 1. config.toml の [embed] を新しいモデルに書き換える（次元が変わるなら dim も）
# 2. 記憶を新しい座標系に載せ替える
python -m nano reembed

# 3. 新しいモデルのものさしを測り直す
python -m nano calibrate

# 4. 想起が効いているか目で見る
python -m nano recall "妹の名前"
```

`reembed` は最初に `soul/backup/` へスナップショットを取ってから動く。
ノートの本文・リンク・重要度・半減期・状態は一切変わらない。
**変わるのは検索用の座標だけ。** 臓器を取り替えるのであって、記憶を捨てるのではない。

数万ノートあると数分かかる。途中で落ちてもバックアップから戻せる。

> **オフラインと実機も別の空間**として扱われる（`hash@1024` と `multilingual-e5-large@1024`）。
> `--offline` で作った魂をそのまま実機で開こうとすると、同じように止まる。これは意図した挙動。

## キャリブレーション

### なぜ必要か

コサイン類似度の絶対値は、埋め込みモデルごとに全く違う帯に分布する。

| | 無関係な文どうしの類似度 |
|---|---|
| ハッシュ埋め込み（`--offline`） | ≈ 0.0 |
| 対比学習で訓練されたモデル（multilingual-e5 など） | ≈ 0.7〜0.8 |

同じ `0.32` という数字が、前者では「ほとんど通さない」、後者では「全部通す」になる。
**絶対値のしきい値は移植できない。**

だから、しきい値は「平均から何σ（標準偏差）離れているか」で持つ。
そのために必要な平均と標準偏差を、**あなた自身の記憶を使って**実測するのが `nano calibrate`。

```bash
python -m nano calibrate
```

- 記憶が30件以上あればそこから最大2000ペアを測る（自分の記憶の分布こそが正しい基準）
- 足りなければ同梱の日本語プローブ文40本で測る
- 隣り合う発話のドリフト（話題の変わり具合）も測る
- 結果は `soul/calibration.json` に保存され、以後しきい値がこれを基準に決まる

**設定ファイルを勝手に書き換えることはしない。** 数字を見せて、判断は人間に渡す。

### 出力の読み方

```
記憶どうしの類似度:
  平均 +0.781 / 標準偏差 0.062
  中央値 +0.784 / 上位10% +0.859 / 上位1% +0.912

設定値（左: config.toml の絶対値 / 右: 実測に基づく実効値）
  pipeline.link_min_similarity（σ換算後の実効値）
      0.320  →  0.874
```

左右が大きく離れているほど、**絶対値のままでは壊れていた**ということ。
上の例なら 0.32 は全ペアを通してしまい、記憶グラフが完全グラフになる（＝リンクが意味を失う）。

σ を調整する目安:

| 設定 | 既定 | 上げると | 下げると |
|---|---|---|---|
| `pipeline.link_min_sigma` | 1.5 | リンクが厳選される。グラフは疎になり、連想は鋭くなるが繋がりを取りこぼす | 何でも繋がる。ハブ記憶が想起を独占しはじめる |
| `pipeline.segment_drift_sigma` | 1.0 | 会話を切らない。1エピソードが長くなり要約が粗くなる | 細かく切れる。話題ごとに分かれるが文脈が分断される |
| `decay.consolidate_sigma` | 2.0 | 統合が慎重になる。cold な記憶が個別に残り続ける | よく統合される。細部が早く失われる |

いじったら `nano recall "…"` と `/why` で実際の想起を見ること。
数字だけ見ていても、記憶の効き方は分からない。

### いつ測り直すか

- 埋め込みモデルを差し替えたとき（`reembed` の直後）
- 記憶が大きく増えたとき（最初はプローブ文で測っていたのが、自分の記憶で測れるようになる）
- 想起の当たり方が変わったと感じたとき

`nano stats` に最後に測った日が出る。未測定なら、設定の絶対値がそのまま使われている。
