# アーキテクチャ

## 第一原理

> 人格と記憶は「モデルの重み」ではなく「自分のディスク上のデータ」に宿らせる。

ここから出てくる帰結を、実装上の禁則として先に書いておく。

1. **記憶ストアに外部サービスを使わない。** サーバー常駐のDBもクラウドも使わない。魂は1ファイルで持ち運べること。
2. **生ログを削除する経路を作らない。** 忘却は状態遷移であり、削除ではない。
3. **平文ミラーを常に維持する。** このコードが読めなくなっても記憶が読めること。
4. **抽象化フレームワークを噛ませない。** LangChain / LlamaIndex / Letta / mem0 のような層の寿命は、このプロジェクトの寿命（一生）より短い。

## InferenceGate — 「無意識は意識に譲る」の実装

VRAM 8〜16GB では、対話用モデルと背景ジョブ用モデルを同時に常駐できない。
そこで推論はすべてゲートを通す。

- 対話は `PRIORITY_CHAT`（0）、背景ジョブは `PRIORITY_BACKGROUND`（10）
- 高優先度の要求が来ると、占有中の低優先度ジョブの `CancelToken` が立つ
- 生成ループはトークンごとに `raise_if_cancelled()` を呼び、`Preempted` で抜ける
- 中断されたジョブはキューに戻る（＝考えかけたことは、あとで考え直される）

比喩ではなく、これが実装上の「無意識」の定義になっている。

デーモン（M2）は `nano chat` とは**別プロセス**なので、threading のロックでは届かない。
`SharedInferenceGate` が `soul.db` の `model_lease`（1行だけの表）をリースとして使い、
プロセス内の排他の外側にプロセス間の排他を重ねている。保持者が死んでも
リースの期限切れ（10秒）でモデルは戻ってくる。

ファイルロックにしないのは `fcntl` が Windows で使えないため。
常駐先が Windows である以上、SQLite で完結させるほうが移植性が高い。

## 書き込みパイプライン

```
生ログ ─① セグメント化─▶ ② 要約 ─▶ ③ 原子化 ─▶ ④ 属性付与 ─▶ ⑤ 埋め込み
                                                              │
                                    ⑦ 固有名詞 ◀───────────────┤
                                                              ▼
                                        ⑥ リンク形成（＋既存記憶の文脈を書き換える）
```

- **①** 時間の空白（既定45分）と、埋め込みのドリフトで話題の切れ目を検出する
- **③④⑦** は1回のLLM呼び出しにまとめる。VRAM 8〜16GBでは呼び出し回数がそのまま体感速度になる
- **⑥c** が A-MEM の肝。新しい記憶が入ると既存の記憶の文脈も書き換わる。記憶は貯める箱ではなく、入るたびに全体が組み変わるもの
- 関係判定は1エピソードあたり `link_judge_budget`（既定6）回まで。予算を超えた分はベクトル類似だけで `similar` を張る

1エピソードあたりの LLM 呼び出しは「要約1 + 原子化1 + 関係判定 最大6」。

## 想起

`docs/memory-model.md` に詳しい。要点だけ:

- 4つの成分（類似度・重要度・想起可能性・リンク次数）を**候補集合の中で 0..1 に正規化してから**重み付けする
- 正規化しないと重みが意味を失う。埋め込みのコサインは狭い帯に固まるので、生の値のままでは他の成分に押し潰される
- 上位ノートから links を1ホップ辿る＝連想。連想で来た記憶は 0.9 倍に割り引く
- MMR で内容の重複を落とす
- 想起されたノートは強化される（半減期が伸びる）

- **セッション内**: 直近ターン（既定12）をそのままメッセージに積む
- **セッション間**: 記憶。ただし会話が記憶になるのは書き込みパイプラインを通ってから
