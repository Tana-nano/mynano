# 記憶モデル

## スキーマ

`src/nano/store/schema.sql` が正。ここは意図の説明。

| テーブル | 何のためにあるか |
|---|---|
| `events` | 生ログ。追記専用。**削除する経路を作らない。** 魂の一次資料 |
| `episodes` | 会話の塊。要約の単位であり、ノートの出所 |
| `notes` | 記憶ノート。1ノート1事実。想起の主役 |
| `note_vectors` | 埋め込み。float32のBLOB。numpy にも `array` にも読める素朴な形式 |
| `notes_fts` | 明示検索用（trigram） |
| `links` | 記憶グラフ。連想の実体 |
| `entities` / `note_entities` | 固有名詞インデックス |
| `working_state` | 常にプロンプトへ載る作業状態。無意識が意識に触れる唯一の窓口 |
| `working_state_log` | 上の書き換えの監査ログ。**人格が勝手に変わっていないか追える** |
| `jobs` | 無意識のジョブキュー（M2で使う） |

### notes.state — 忘却の全体

```
 active ──（想起可能性がしきい値を割る）──▶ cold ──（クラスタが統合される）──▶ merged
   ▲                                          │                                   │
   └───────── 明示検索でいつでも掘り起こせる ───┴───────────────────────────────────┘
```

- `active` … 通常の想起の対象
- `cold` … 通常の想起からは外れる。`/recall` の明示検索では出る
- `merged` … 上位ノートに統合された。`merged_into` と `merged_from` リンクで親から辿れる

**どの状態でも行は消えない。** 不可逆な削除はユーザーが明示的に命じたときだけ。
「消えて困る記憶が消える」のは、一生モノの相棒として致命的だから。

## 想起スコア

```
score = w_sim·norm(類似度) + w_imp·norm(重要度) + w_rec·norm(想起可能性) + w_con·norm(log1p(次数))
```

`norm` は**候補集合内での min-max 正規化**。これが要点。

生のコサイン類似度は、埋め込みモデルによって狭い帯（e5 なら 0.7〜0.9 など）に固まる。
正規化せずに重要度（0〜1をフルに使う）と足すと、関連度の差が押し潰されて、
重要でよく繋がった記憶が何を聞いても上位に出てくるようになる（実際に起きた）。
Generative Agents が各成分を正規化しているのは同じ理由。

成分の意味:

| 成分 | 何を表すか |
|---|---|
| 類似度 | いま話していることとの意味的な近さ |
| 重要度 | 忘れたら困る度合い（LLMが記憶化のときに自己評価） |
| 想起可能性 | 忘却曲線の現在値。最近触れた記憶ほど高い |
| 次数 | どれだけ他の記憶と繋がっているか。よく繋がった記憶は思い出しやすい |

そのあと **1ホップのグラフ展開**（連想）と **MMR**（重複除去）を通す。
連想で来た記憶は 0.9 倍に割り引く。本人が探しに行った訳ではないので。

## 忘却曲線

```
retrievability(t) = exp(-(t - last_accessed) / half_life)

half_life = base_half_life_days × (1 + importance_span × importance²)
```

重要度を**二乗で**効かせている。線形（`base + bonus × importance`）にしていたときは、
重要度0.5の「職場は代々木」が30日で cold になった。人間はそうは忘れない。
桁を分ける必要がある。

| importance | 初期半減期 |
|---|---|
| 0.1（雑事） | 約 6日 |
| 0.3 | 約 38日 |
| 0.5 | 約 102日 |
| 0.7 | 約 198日 |
| 0.9（名前・約束） | 約 326日 |

### 強化（間隔反復）

半減期は触れられるたびに伸びる。

```
half_life ← min(half_life × (1 + gain × (0.5 + importance)), max_half_life_days)
```

伸びる契機は2つ:

1. **想起** — 会話の中で実際に思い出された（`gain = recall_gain`）
2. **連想** — 関連する新しい記憶が入ってきた（`gain = recall_gain × 0.5 × 関連の強さ`）

2つ目が無いと、一度話しただけの事実は二度と触れられずに消える。
ただし効き方を関連の強さに比例させないと、どうでもいい記憶が連想の巻き添えで生き延びる
（これもベンチで実際に起きた）。

### 統合

cold なノートをコサイン類似度で貪欲にクラスタリングし、
`consolidate_min_cluster` 件以上まとまったら1枚の上位ノートに要約する。
元ノートは `merged` として残り、`merged_from` リンクで親から辿れる。

## 品質をどう保つか

記憶システムは「なんとなく良くなった気がする」で壊れていく。数字で見る。

```bash
python tests/bench/memory_bench.py
```

- **想起率** … 会話に埋めた12個の事実を、0/7/30/90日後に思い出せるか
- **忘却率** … 混ぜた8個の雑事が、能動インデックスから外れているか

重み・半減期・パイプラインを触ったら必ず両方を見ること。
片方だけ良くするのは簡単で、意味がない（全部覚えればいい／全部忘れればいい）。
