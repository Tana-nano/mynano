# 仕様 (/vrc-spec)

目的: 実装者（= 自分）が迷わず書け、テストで「動いた」と言える仕様にする。

## 手順

1. `products/<name>/docs/concept.md` を読む。無ければ `/vrc-concept` へ戻る。
2. 外部仕様を一次情報で確認し、URL を `spec.md` の「出典」に残す:
   - VRChat OSC: https://docs.vrchat.com/docs/osc-overview （アドレス、型、ポート）
   - VRChat ログ: `shared/fixtures/output_log_sample.txt` と実ログの差分に注意（形式は変わる）
   - 外部ツール（OyasumiVR、OBS websocket 等）は GitHub の README / docs
3. `spec.md` と `test-plan.md` を書く。
4. オーナーに「仕様の要点 5 行＋判断が必要な点」を提示して確認を取る。
   確認が要らない細部は自分で決めて仕様に書く。

## spec.md の構成

```
# <商品名> 仕様  vX.Y

## 概要（1段落）
## 対応環境 / 前提ソフト
## 入力
  - OSC 受信: アドレス / 型 / 送信元 / 頻度
  - ログ: 監視パス（既定 %LOCALAPPDATA%Low\VRChat\VRChat\output_log_*.txt）、対象行の正規表現
  - 設定ファイル: 形式 / 既定値 / 置き場所
## 出力
  - OSC 送信 / ファイル / 画像 / OBS 操作 など
## 画面 / CLI
  - 各画面 or サブコマンドの役割と項目
## 状態遷移・主要ロジック
## エラーと復旧（VRChat 未起動、ポート競合、ログ形式不一致、権限）
## 設定項目一覧
## 既知の制限・未検証事項（実機でしか確認できないもの）
## セキュリティ / プライバシー（他人の表示名を保存する場合の扱い）
## 出典
```

## test-plan.md の構成

- ユニット: 純粋ロジック（解析、集計、スコア）
- 結合: `shared/vrc_mock` を使った OSC 往復、ログ追記→検出
- フィクスチャ: `shared/fixtures/` に置くサンプルと、その由来
- 手動確認（オーナー or 購入者に頼る項目）: 最小限にし、README の「既知の制限」と一致させる

## ルール

- 仕様に無い機能は実装しない。追加したくなったら spec.md を先に更新する。
- 数値の既定値（ポート、閾値、間隔）は全部設定可能にし、既定値の根拠を書く。
- 他人の表示名・ユーザー ID を保存する機能は、保存先・削除方法・公開しない旨を仕様に書く。
